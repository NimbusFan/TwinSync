# 体积与运行开销

测试日期：2026-11-13。以下是本机的短时隔离测量，不能代表所有电脑或大文件传输的峰值。

## 发布体积

早期测量的安装器约 675 KiB，干净解压约 1.42 MiB。清理后只交付安装器 EXE 和源码 ZIP；不分发便携包、浏览器、Node.js、测试目录或本机数据。开发缓存、重复资源及旧运行目录均已清理，实际文件大小以 `dist` 的当前输出为准。

## 同步核心的早期基线

使用发布版原生服务，在独立进程中加载 10,000 条合成文件索引，无配对设备、不进行文件传输。等待 2 秒后，采样空闲状态 5 秒。

| 指标 | 本次结果 |
| --- | ---: |
| CPU，按一个逻辑核心计 | 0.00% |
| 工作集 | 83.49 MiB |
| 私有提交内存 | 76.77 MiB |

此进程仅启动同步核心和本地 HTTP 服务，不含 Windows 托盘 UI 或浏览器。实际文件扫描、索引增长、冲突处理和持续传输的峰值尚未测试。

## 本轮索引保存优化

保持原有 JSON 字段和数据内容，取消保存时的整份索引深拷贝，直接流式写入临时文件后提交。加载时释放解析数组与条目之间的容器关联，避免旧快照被条目间接保留。以下为相同的 10,000 条合成索引，在独立测试程序中的结果。

| 指标 | 原实现 | 本轮实现 |
| --- | ---: | ---: |
| 加载后托管内存 | 40.58 MiB | 40.46 MiB |
| 保存后托管内存 | 68.10 MiB | 40.46 MiB |
| 单次保存时间 | 92 ms | 27 ms |
| 常驻重复条目快照 | 有 | 无 |

内存数据在测试程序中执行垃圾回收后读取，仅代表该索引测试进程的托管堆，不是整个应用的工作集。生产代码没有通过强制垃圾回收来降低数值。保存时间为单次观察值。

回归验证覆盖普通条目、删除标记、Unicode 路径、大小写查找、额外元数据、修订号、时间戳、冲突记录、原地修改保存和 10,000 条索引重新加载。新增写入失败测试，确认旧文件保留且临时文件清理。Windows 下可运行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-native.ps1` 重现当前原生回归检查。

## 网页与特效

本轮已恢复桌面和手机的 30fps 上限及动态背景光晕，保留 520 / 160 颗粒子、连续亮度变化、粒子光晕、鼠标交互和玻璃折射。上一轮采用 20/15fps 的测量不用于评价本轮效果。

使用独立无头 Chrome，1440 × 1000 视口、520 颗粒子、30fps 目标和动态光晕，启用硬件加速，GPU 为 RTX 4060。页面加载约 2.2 秒后，每种状态采样约 3.5 秒。本轮有效复测没有与界面回归测试并行运行。浏览器数据包含该独立浏览器的所有进程，不能当作用户现有浏览器中新增一个标签页的增量。

| 指标 | 原始实现基线 | 本轮同规格短时复测 |
| --- | ---: | ---: |
| 前台 CPU，按一个逻辑核心计 | 61.62% | 31.37% |
| 前台私有提交内存 | 514.45 MiB | 336.83 MiB |
| 隐藏时粒子动画 | 停止 | 停止 |
| 隐藏时状态事件连接 | 仍在重连 | 已关闭 |

本机有 20 个逻辑核心，所以上述前台 CPU 换算为整机百分比，约从 3.08% 降至 1.57%。GPU 占用未单独测量；内存是私有提交量，不能与任务管理器的物理工作集直接等同。采样时间较短，数值用于定位开销和比较本次改动。

## 已实施的优化

- 预渲染粒子和光晕到共享图集，逐帧复用位图，保留原来的粒子半径、连续透明度、密度及动态背景。
- 玻璃折射贴图按形状缓存；逐像素计算改用标量比较，避免为每个像素分配数组。
- 索引保持原有格式，流式保存，取消完整 JSON 字符串和常驻重复索引快照。
- 鼠标高光合并到动画帧处理，减少高频布局读取和样式更新。
- 网页隐藏时关闭状态事件连接，暂停状态轮询、配对倒计时和相对时间刷新；显示后恢复。

关闭管理页后，网页动画不在同步核心中运行。包体已较小，后续优化更应关注大目录索引内存、文件变化时的扫描范围，以及真实双机同步的 CPU、磁盘和内存峰值。

## 传输与历史版本维护

新版设备间按最大 4 MiB 校验块续传，网络与磁盘读写采用 64 KiB 缓冲，不把整个文件载入内存。接收端在分块校验和落盘后确认位置，中断的块回退到上一个确认位置。重连时重新核对前缀，完成后再校验完整 SHA-256。续传进度包含此前完成的字节，速度只计算本次连接实际传输的字节。回归使用隔离文件检查进度和内容一致性，这不是吞吐量或运行内存的性能基准。

历史版本清理会实际回收无引用的内容文件；正常备份只检查受本次保留规则影响的候选内容，完整孤立文件检查按小时进行，修改保留设置时也会触发。正在恢复和仍被其他版本引用的内容不会被回收。批量恢复开始时暂时保留全部选中版本，避免前一项的恢复前备份删掉后续项目。文件替换增加提交前内容校验和临时文件提交步骤，用于保护传输期间的新编辑和替换失败时的原文件。

## 增量扫描与文本预览

文件监视事件按文件夹排队，重复路径合并，目录改名同时处理原路径和新路径。单文件变化只核对该路径；目录变化只核对该子树。同一文件夹与多台设备同步时只扫描一次。监视缓冲区溢出后执行完整扫描；正常情况下每十分钟完整核对，没有可用监视器时每三十秒回退扫描。手动同步或核对仍执行完整扫描。

文本对比先读取有限分段，再解码和计算段内差异。每次读取不超过 64 KiB，最多显示 32,768 个字符或 200 行，不再先读取完整文件。历史版本下载使用流式响应。日志按四份、每份 512 KiB 轮转，内存只保留最近 300 条记录。
