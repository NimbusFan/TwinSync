# 桌面原生版安全边界

安全改动适用于 `TwinSync.exe` 原生 Windows 服务，要求 Windows 10/11 和 .NET Framework 4.7.2 或更高版本。源码包只保留此原生实现。

## 设备通信

- 设备连接使用 TLS 1.2；HTTP 设备请求直接拒绝，不允许明文回退。
- 首次配对需要从对方设备页复制完整 SHA-256 证书指纹，通过可信渠道核对。连接前固定核验指纹，错误指纹无法完成配对。不要从尚未信任的网络响应中取得指纹再直接信任它。
- 6 位配对码 10 分钟有效，成功后轮换；10 分钟内累计 8 次错误后锁定，用户可在本机刷新。已配对设备以设备 ID 和随机令牌共同认证。
- 移除或暂停设备后拒绝其访问；旧设备必须更新并重新配对，不会默默继续使用旧协议。
- 文件传输后核验 SHA-256；未收完整或哈希不符的上传不会覆盖目标文件。提交前再次检查本机内容和授权，已有文件采用原子替换，替换失败不删除旧文件。下载和历史恢复使用同一写入保护；传输临时文件不会被扫描为普通同步文件。连接数量有上限，JSON 请求体有大小限制。

## 用户授权

首次运行不设置设备名称、不扫描或添加任何同步目录。同步目录由用户手动选择并授权，远端共享邀请也必须先选择本机目录并确认。

配对只建立设备信任。共享邀请只发送文件夹 ID 和名称，不发送本机绝对目录；接收方必须选定自己的本机目录。远端不能替本机创建任意路径，也不能自动扩大现有目录的授权。

文件下载、清单、写入、删除和确认操作均检查目录授权与暂停状态；仅发送目录拒绝远端写入和删除。路径检查按目录边界校验，拒绝绝对路径、父目录跳转、NTFS 附加数据流和保留设备名；扫描不跟随符号链接或目录联接，访问时也会检查联接。不能将应用身份、配置或版本库所在目录加入同步范围。

文件定位读取经过同样边界校验的请求路径，由 Windows Shell 打开目录并选中文件，不执行选中的文件。定位操作仍需通过管理面板与 CSRF 校验；仅在显式请求且原有前台窗口和输入状态尚未改变时请求窗口激活。

更换已授权目录必须显式确认迁移，服务端复制并校验原有文件，拒绝覆盖新位置中内容不同的同名文件，拒绝新旧目录互相包含，检查新位置没有缺失索引中的有效文件。原目录保留，迁移后强制暂停并重建监听器；恢复前由用户核对。同步过程中拒绝改变目录、同步方向和忽略规则；暂停、移除设备或文件夹、修改共享范围会使原有任务授权失效。传输分块、发送文件响应和最终写入、删除、确认操作均重新检查当前授权；重新启用不能令旧授权恢复。共享通知按文件夹和设备串行发送，并读取最新配置。

单文件夹和单设备同步由服务端限制任务范围，不能仅依赖前端按钮。失败与跳过不会被记录为整体成功，错误详情包含相应的文件夹、设备和文件路径，供用户核对后按原范围重试。

## 本机管理与存储

管理面板默认仅本机可用。Host、Origin 和浏览器跨站来源检查配合独立随机 CSRF 令牌；页面设置同源资源、禁止外部脚本与框架嵌入的响应策略。状态、设备更新和设备连接响应不包含设备密钥或配对令牌。

远程管理只有主动开启后才可用，必须通过 HTTPS 和随机管理链接建立会话；使用 Secure、HttpOnly、SameSite=Strict Cookie，链接中的凭据进入会话后从地址栏移除。随机管理链接在服务重启后失效，不应分享给其他人。浏览器首次访问自签名 HTTPS 证书时需核对证书；默认的本机 HTTP 管理页只在 loopback 访问，设备间文件通信仍使用 TLS。

证书私钥和设备令牌由 Windows 当前用户的 DPAPI 保护。不能把含身份数据的整个 `data` 目录当作可跨电脑使用的账户；恢复时应使用原 Windows 用户配置。跨电脑重新安装应使用干净安装包，重新命名、选择目录和配对。数据目录中现有文件、索引和版本记录不会因设备配对或授权目录迁移而删除。

IP、配对码及主机详细信息默认隐藏，这是减少截图和旁观泄露的界面措施；实际访问保护由服务端承担。多网卡信息来自系统，优先显示有网关的网络，其他网卡按需展开；程序无法仅凭网卡名称保证它一定是另一台电脑可达的网络。

登录启动使用当前用户的 Windows Run 项，记录经过参数转义的程序路径、数据目录和端口，并附带后台启动参数；不注册系统服务或提升权限。关闭设置、卸载或改变安装位置时，只移除或更新指向本安装的启动项。注册失败会返回错误，不会将设置显示为已成功启用。

## 保护范围与限制

这些措施不能保证两台电脑的绝对安全，也不能防御已控制本机 Windows 用户账户的恶意软件、被授权设备的恶意修改、文件内容中的恶意代码或网络拒绝服务。DPAPI 不加密同步文件、历史版本和普通元数据；需要静态数据保护时，可使用 Windows 的磁盘加密和独立账户权限。

版本历史保留原有功能，但不是独立备份。对重要文件应保留另一份离线或独立版本备份。此版本经过隔离功能和安全回归测试，尚未经过独立安全审计。

版本回收先持久化保留记录，再删除没有引用的内容文件。按内容去重时，其他文件夹或路径的有效引用同样受到保护；恢复时暂时保留所选内容，避免「恢复前备份」触发数量清理后删掉正在恢复的版本。元数据保存失败不回收旧内容。清理仅针对版本库中符合内容哈希命名和目录规则的文件，不遍历同步目录删除文件。

实现依据：[Microsoft TLS 与 .NET Framework](https://learn.microsoft.com/en-us/dotnet/framework/network-programming/tls)、[OWASP CSRF 防护](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)。

## 验证

`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-security.ps1` 在 `.test-tmp` 下启动两个隔离的原生服务，覆盖正确/错误指纹、明文拒绝、CSRF、来源和 Host 检查、密钥脱敏与 DPAPI 重新加载、用户命名、共享邀请确认、不同本机路径上的双向传输、覆盖前版本保存、路径越界、未共享删除和确认操作、暂停、设备撤销与配对限流恢复。不操作实际同步目录。

`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-workflows.ps1` 通过三个隔离服务覆盖文件夹和设备范围、离线与文件级失败、失败时间戳、迁移确认、复制保留、迁移后暂停、同名冲突与嵌套目录拒绝，以及启动设置失败回滚。扩展用例覆盖修改时间与修订号相反时的冲突策略选择、原子替换失败保留原文件、未扫描本地新编辑、接收途中撤销共享及暂停或移除设备和文件夹、重新共享后旧任务仍失效、版本共享引用与过期回收、只保留一个版本时的恢复、损坏备份拒绝、文件字节进度和小 POST 请求体的响应完整性。`scripts/test-tray.ps1` 对启动项使用唯一测试注册表路径，验证后台参数、路径转义、安装位置更新和卸载归属检查。
